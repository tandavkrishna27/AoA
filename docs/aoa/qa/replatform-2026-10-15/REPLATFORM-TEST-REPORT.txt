HOW LOCAL AND VPS DELEGATION WAS TESTED

A shared environment has one logical control-plane authority, which may have multiple replicas. Workers enroll into that authority. Two complete AoA installations with independent databases do not delegate to each other as peer applications.

Both cross-host directions were tested as separate fixture environments. A private SSH tunnel carried control traffic; a test-only ingress bridge/host allowlist allowed the Docker Desktop path. This differs from the original hermetic network topology.

The later successful VPS-to-PC job used the VPS test authority and a separate local Docker worker/reference provider. It did not use the public Google-authenticated app, the native port-3210 app, or the user’s personal Codex login. A real local Node environment probe and unique result marker establish where that bounded fixture executed; ordinary reference-provider output is scripted.

The native local application independently completed a real Codex subscription Commander turn. Combining that personal subscription with a VPS-issued task needs the unimplemented device-local credential/execution path. Copying auth files to the VPS was not used.
