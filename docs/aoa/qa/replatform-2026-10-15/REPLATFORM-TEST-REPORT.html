How local and VPS delegation was tested

A shared environment has one logical control-plane authority, which may have multiple replicas. Workers enroll into that authority. Two complete AoA installations with independent databases do not delegate to each other as peer applications.

Both cross-host directions were tested as separate fixture environments. A private SSH tunnel carried control traffic; a test-only ingress bridge/host allowlist allowed the Docker Desktop path. This differs from the original hermetic network topology.

The later successful VPS-to-PC job used the VPS test authority and a separate local Docker worker/reference provider. It did not use the public Google-authenticated app, the native port-3210 app, or the user’s personal Codex login. A real local Node environment probe and unique result marker establish where that bounded fixture executed; ordinary reference-provider output is scripted.

The native local application independently completed a real Codex subscription Commander turn. Combining that personal subscription with a VPS-issued task needs the unimplemented device-local credential/execution path. Copying auth files to the VPS was not used.

Interpreting the suite counts

The lanes overlap; their test counts must not be added into a unique-test total. A composite node:test recovery test contains multiple checks but is still one test. Counts labeled per host are independent executions of the same assertions.

The initial Node 26 run is preserved as failed evidence. The supported Node 24 result supersedes it for the current normal-lane verdict; isolated repeats do not erase failures or establish the three-run stability requirement.

The explicit Windows manifest selects the 123 test files that mention AOA_RUN_WIN_INTEGRATION, enables that flag, and executes serially with the real embedded PostgreSQL prerequisites. Its JSON manifest is retained. Any remaining skips are still excluded from the passing count.

All123 Windows file reports completed, but the PowerShell5 wrapper raised NativeCommandError while Vitest wrote its final stderr report. Windows counts are therefore summed from those complete per-file reports; the final native exit, global uncaught-error count and final duration were not captured. Unknown is not zero. The original UTF16LE log and a decoded UTF8 copy are retained. Focused direct-Node runs capture final reports separately; they do not replace the whole-lane failure.

The normal Windows suite leaves platform/live/integration opt-ins skipped. Full browser-provider acceptance, Linux kernel/socket assertions and other operating systems require their own lanes. Source-history test totals quoted in milestone documents are prior developer evidence, not counts from this session.
