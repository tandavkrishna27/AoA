# M3 guest application session establishment

The named guest component is `createSessionCredentialMailbox`. The trusted runner config may include `sessionCredential: { bindingId, origin, cookieName }` only when the control-plane application-session issuer is configured. An absent binding keeps anonymous browsing. The origin must be an exact allowlisted HTTPS origin and the name must start with `__Host-`. Trace recording with a session credential is refused, because trace network metadata can contain cookie headers.

The component emits only `{ type: "session_credentials_requested", requestId, bindingId, policyDigest, expiresAt }`. It waits at most 30 seconds for `/home/user/.aoa/browser-session-credentials/{requestId}.json`. The request's expiry caps cookie lifetime at five minutes; the control-plane issuer also caps delivery at the live lease and session lifetime.

The strict reply is `{ requestId, bindingId, policyDigest, origin, expiresAt, cookie: { name, value } }`. Extra fields, including Domain, token bundles and refresh tokens, are rejected. The reply is bounded to 8192 bytes; its cookie value is 16–4096 characters in `[A-Za-z0-9._~-]`. A future canonical ISO expiry, matching identity, policy digest, origin and name are mandatory. Symlinks, hardlinks and changed files are refused. The file is unlinked before injection; failure to consume it refuses authentication. Errors contain a fixed coarse reason.

The Playwright driver injects the resulting host-only cookie with Secure, HttpOnly and SameSite Strict before any navigation. No localStorage, page script token or arbitrary storage-state payload is accepted. Since cookies do not scope by port, request routing refuses the credential-bearing host on any other port, even if a separate network rule permits it. Expired session authority also refuses requests. Graceful close and interrupted injection clear context cookies before closing; sandbox destruction remains the outer profile cleanup.

The guest verifies the staged reply's binding; it cannot independently consult the live control-plane fence. The production issuer and worker delivery must authorize the matched request under that fence, exchange the connector credential at a trusted application login endpoint, and deliver only the resulting scoped cookie through protected one-use staging. Connector access/refresh tokens remain in the control plane. Staging must prove encrypted storage, short expiry and deletion; missing authority or protection refuses issuance. No cookie bytes pass through worker protocol messages.

Guest tests cover an actual keyless HTTPS application fixture: anonymous access is refused and the injected cookie authenticates the same endpoint. JavaScript cannot read it. Hostile scope, identity, digest, expiry and token fields, timeout, cancellation and lease-loss signals are refused. This guest control does not claim the independent control-plane broker and worker delivery are complete.
