## TK Decisions

1. **Protected input set and custody.** Identify the exact controller-owned files, project, environment keys and their approved private provenance for each mode. The record must bind values or private value hashes as well as file hashes; a changed substitution value with unchanged files requires a new render and handoff. State who can update the protected inputs and how the signed session revision is pinned.
2. **Complete render profile.** Approve every expected service, dependency, image/endpoint and sensitive-field rule for the new candidate, including not-yet-created adapter-manager in the render profile. Keep the execution profile separate; keyless execution must still refuse adapter-manager. Obtain independent consistency review for identities and edges shared with the execution profile.
3. **Private resource limits.** Set maximum complete stdout bytes, maximum stderr bytes, command timeout and any lower response/code-count bounds. A started command that exceeds a limit becomes unknown or refusal per the spec; no truncation can pass.
4. **Stable result codes.** Approve a closed code set and mapping for verifier outcomes. Arbitrary validator messages remain private; an unrelated unscoped violation cannot satisfy the `DISPATCH-DEFAULT` positive control.
5. **Raw rendered evidence.** Decide whether raw merged bytes are required for later independently graded evidence. A digest alone does not establish retention. If raw bytes are required, inventory exact bytes, private destination, access, lifetime and separate upload authorization before any transfer. No blank advance upload approval is requested here.
